# Практическая работа №5. Аналитическое приложение поликлиники

Учебный проект по дисциплине «Базовые и прикладные информационные технологии». Предметная область: ГБУЗ «Городская поликлиника № 8 ДЗМ», филиал № 2. Данные вымышленные, не являются сведениями реальных пациентов.

## Запуск и GitHub Pages

1. Распаковать ZIP, открыть папку в VS Code.
2. Для локальной проверки открыть терминал в папке с `index.html`, выполнить `python -m http.server 8000`, перейти по адресу `http://localhost:8000/`. Альтернатива — расширение Live Server.
3. Для публикации создать репозиторий GitHub и загрузить **содержимое** папки проекта (не сам архив). `index.html` должен находиться в корне выбранной папки публикации. В Settings → Pages выбрать Deploy from a branch → main → / (root) → Save.
4. Открыть опубликованную страницу по адресу, который покажет GitHub Pages. Сервер, MySQL и установка npm-пакетов не требуются.

База IndexedDB создаётся в браузере при первом запуске. В другом браузере или на другом домене она создаётся отдельно. Все пять таблиц загружаются из `data/seed.js`, после чего интерфейс читает их из IndexedDB. Раздел «О проекте» показывает количество записей в хранилище, позволяет перечитать или восстановить учебные данные. Не загружайте реальные медицинские данные и пароли в публичный репозиторий.

## Структура

- `index.html` — интерфейс.
- `style.css` — адаптивное оформление.
- `app.js` — подключение IndexedDB, обработка, расчёты, графики SVG, экспорт.
- `schema.svg` — физическая схема пяти таблиц MySQL.
- `data/seed.js` — нормализованные записи для начальной загрузки.
- `data/data.csv` — расширенная выгрузка реестра для внешней аналитики.
- `sql/hospital_setup.sql` — исходная схема и данные практики №3.
- `sql/01_add_data.sql` — дополнение практики №4.
- `sql/03_expand_data.sql` — дополнение практики №5 для существующей базы bipit_practice3_demo после практики №4 (однократно).
- `sql/practice5_full.sql` — самостоятельный вариант создания и заполнения новой MySQL базы clinic_practice5 (однократно). Не удаляет предыдущую БД. Это дополнительный исходник для защиты, браузер не обращается к MySQL.
- `sql/02_export_data.sql` — запрос выгрузки всех 1500 приёмов; для новой базы clinic_practice5 заменить команду USE в начале файла.

## Контрольные значения (при сброшенных фильтрах)

- 1500 приёмов, 200 уникальных пациентов.
- Среднее ожидание 23,7 мин (с заполнением пропусков медианой).
- 443 критические задержки, доля 29,5%.
- Терапевтическое отделение: 821 приём, среднее 26,90 мин; кардиологическое: 495, 21,55 мин; хирургическое: 184, 15,26 мин.
- 669 учтённых смен, 54 критические смены терапевтов (от 35 пациентов).

Порог ожидания: меньше 15 мин — норма, 15–19 — выше плана, 20–29 — предупреждение, от 30 — критично. Порог нагрузки применяется только к терапевтам; план 25, от 30 предупреждение, от 35 критическое значение. Корреляция Пирсона — между ожиданием, возрастом и количеством наблюдений врача за дату; не между ID и номерами кабинетов. Корреляции и управленческие наблюдения не доказывают причинность, данные учебные.
